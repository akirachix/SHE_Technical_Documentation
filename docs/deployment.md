## 8.2 Environment Configuration
Production environments are governed strictly through runtime injection of environment variables. No secrets, credentials, or encryption keys are committed to the code repositories. The following baseline configuration matrix must be established within the respective hosting consoles:

<div class="ai-arch-code-wrapper" autocomplete="off">

```env
# --- Core Engine & Database Secrets ---
GEMINI_API_KEY=AIzaSy...              # Auth token for Google Gemini Model & File Search
DATABASE_URL=postgres://...           # Secure connection URI for Heroku Postgres
JWT_SECRET_KEY=prod_sec_hash...       # Cryptographic key for OAuth2 token signatures
PHONE_ENCRYPTION_KEY=aes_pad...       # Symmetric key for handling player PII metadata

# --- System Administrator Defaults ---
ADMIN_EMAIL=admin@dadasafe.org        # Seeded system admin verification address
ADMIN_PASSWORD=secure_seed_pass...   # Seeded system admin fallback credential

# --- Transactional Communication / Resend Core ---
SMTP_SERVER=://resend.com           # Resend SMTP relay routing address
SMTP_PORT=587                         # Secure transport protocol port
SMTP_USERNAME=resend                  # Authenticated sender username
SMTP_PASSWORD=re_prod_pass...        # Authenticated sender api key credential
SMTP_FROM=security@dadasafe.org       # Authoritative platform outbound alias

# --- Network Routing Guards ---
ALLOWED_ORIGINS=["https://*.vercel.app","http://localhost:3000"] # CORS Origin rules
```

## 8.4 Web Deployment
The Next.js administrative and support provider client architectures are deployed directly through Vercel's global edge network.

* **Pipeline Setup:** Vercel is connected via Git integration webhooks directly to the software repository.
* **Compilation Trigger:** When an authorized pull request or change is merged into the production branch, Vercel pulls the tree, reads the framework configuration, applies optimization variables, and distributes the compiled static and dynamic assets across its Global Edge Network.

## 8.5 Mobile Build
The player-facing client is generated through a localized Flutter compilation process, which feeds into a cloud-based layout streaming service for rapid internal validation.

* **Compilation Protocol:** Engineers execute local release packaging targeting Android architectures using the following terminal script:

<div class="ai-arch-code-wrapper" autocomplete="off">

```bash
flutter build apk --release
```

</div>

* **Virtual Evaluation Pipeline:** The generated `.apk` binaries are uploaded to Appetize.io. This creates a secure, browser-based mobile emulator stream that allows product owners, QA personnel, and UX designers to completely test the player app without manually flashing physical devices.

## 8.6 Database Deployment
Schema modifications, relational constraints, and database tables are handled via Alembic, a robust database migration engine connected to SQLAlchemy / SQLModel.

* **Execution Safeguards:** Structural updates are never executed using direct, unstructured SQL patches. Instead, when database models are adjusted locally, an incremental python migration script is compiled.
* **Deployment Integration:** During backend runtime bootstrap operations on Heroku, Alembic parses the production PostgreSQL database instance via the `DATABASE_URL` string and brings the live data schema up to the latest revision level using the primary delivery command:

<div class="ai-arch-code-wrapper" autocomplete="off">

```bash
alembic upgrade head
```

</div>

## 8.7 CI/CD
The platform avoids complicated external workflow pipelines in favor of a clean, **Git-Triggered Deployment** philosophy.

1. **Branch Isolation:** Engineers execute work, bug fixes, or enhancements within sandboxed local branches.
2. **Code Merging:** Code is checked and reviewed before being merged into the codebase's main integration branch.
3. **Automated Webhook Actions:** The merge event acts as a webhook release trigger. Heroku and Vercel instantly intercept the Git tree update, pulling the clean code down into their respective isolated container setups. This pipeline ensures that verified source changes instantly roll out into live system updates without requiring manual server orchestration.

## 8.8 Monitoring
System visibility relies on the native logging and health infrastructure provided by the cloud vendors.

* **Log Consolidation:** The development and operations teams review operational logs, standard output streams, and application crashes directly through the integrated Heroku Dashboard. Users click into the Logs Bar within the system interface console to monitor real-time errors, routing anomalies, or backend traceback summaries without needing complex terminal access tokens.
* **API Diagnostics:** To confirm system health, backend availability, and the health of the connection to the Heroku Postgres database engine, an explicit ping route is hosted on the system layer. Checking the status is as simple as pinging the health endpoint:

<div class="ai-arch-code-wrapper" autocomplete="off">

```http
GET https://herokuapp.com
```

</div>

A successful handshake returns an `HTTP 200 OK` status code alongside a structured database confirmation payload.

## 8.9 Troubleshooting

<div class="ai-arch-card" autocomplete="off">
    <h3>Alembic Migration Failures</h3>
    <p>If a deployment hangs due to database constraint mismatches, check the Heroku logs panel to find conflicting column definitions. Use a local setup to inspect the migration files, resolve any database lock steps, and run <code class="ai-arch-route-code">alembic upgrade head</code> to fix the schema drift.</p>

    <h3 style="margin-top: 1.5rem !important;">Gemini Context Error Returns</h3>
    <p>When the JSON payload panel prints a configuration mismatch warning, verify that the active database <code class="ai-arch-route-code">GameFile</code> record contains a valid <code class="ai-arch-route-code">gemini_file_name</code> string that perfectly matches the vector collection tag inside your Google GenAI console.</p>
</div>
